# 小说真人短剧漫解 v1

## 目标

把中文小说或故事原文先在内部改编为一行一句的真人短剧漫解剧本，再生成一个可由 AI 出图、出片管线直接消费的 JSON 对象。严格保留改编剧本中的旁白和台词，生成去重资产提示词，并让分镜时长、cNN 子镜头和 `@[类型-名称]` 引用闭环。

本 skill 完全独立：阶段 0–7、按需参考的阶段 08、校验脚本和测试均在自身目录内。不得调用其他 skill，不得读取或依赖其他 skill 的运行时文件。

## 开始前

确认输入同时包含：

- 小说或故事原文；
- 分镜主切割时长 `DURATION_SEC`（整数秒，至少 4 秒）。

标题与全书设定可选。若缺少小说正文，请求用户补充；若仅缺少 `DURATION_SEC`，只询问该参数；不要猜测。输入齐全后再执行工作流。

## 工作流

必须按编号顺序完整执行阶段 0–7。阶段 08 仅在输入格式复杂、改编边界不明确或需要比对成品时按需读取。阶段 0 的漫解剧本只用于内部交接；不要把它作为最终交付物。阶段 0 必须额外保留调试文件 `adapted_script.json`，但最终回复仍不直接输出该文件。

### 阶段 0：小说改编为漫解剧本

当前 Skill Run 工作目录中已由后端机器写入 `source.txt`，内容是完整、原样的小说正文，它是本阶段唯一可信的原文。以 `source.txt` 为准执行改编；输入消息里的正文仅供参考，两者不一致时以 `source.txt` 为准。

先把原文转换为以下纯文本格式，并执行**逐句覆盖、逐句读出**：小说正文每个非空句子都必须有一条或多条剧本旁白/对白承载其完整事实和信息，且必须作为有文本的声音读出。旁白和对白的字词、顺序与事实必须与小说原文完全一致；只允许为形成可直接配音的完整话语补充、替换或移动标点，并删除被标点替代的空白，不得润色、改写、概括、增删字词或合并原文句子。不得仅用画面、资产或镜头描述替代原文句子的声音。

```text
《标题》一行一句剧本版

人物：主角、主要反派、家人、配角、群众角色

【第01场】场景名｜地点｜时间｜内/外
安岁（旁白）：一句叙述。
角色名：一句对白。
```

执行规则：

- 小说原文的剧情、叙述、动作、心理、对白、冲突、反转、爽点和结局必须完整保留；不得增加或修改原文内容。
- 每一行只写一句旁白或一句对白；每条发声行必须构成可直接配音的完整话语，并以 `。`、`！`、`？`、`……` 或表示话语中断的 `——` 结束。原文缺少句末标点时，必须按语气补齐。可按剧情自然分场，但不得写分镜号、镜头描述或拍摄指导。
- 疑问语气词“吗”后若以空白直接连接下一独立分句，必须用 `？` 替换该空白，例如 `你没看到吗 别闹。` 规范为 `你没看到吗？别闹。`。
- 已明确主角姓名时，叙述、动作、心理活动和背景说明统一写成 `姓名（旁白）：`；无法确认主角姓名时才使用 `主角（旁白）：`。有引号的内容和明显人物口语写成角色对白。
- 根据上下文判断说话人；具名人物动作、神态或说话提示紧邻的引号内容，必须归该具名人物。
- 连续引号内容拆行后仍必须保持同一说话人；不得输出孤立的开引号、闭引号或未配对引号。
- 只有原文明确是群体发言时才能使用村民、众人等群体角色；不能因未立即识别说话人就把具名人物对白改为群体发言。
- 第一人称和亲属称谓的正文必须保持原文：不得把正文中的“我”改成主角名，也不得把正文中的“我爸/我妈”等改成父亲、母亲、爷爷等关系称谓。说话人标签不受此限制：主角父母没有明确姓名时，使用主角姓氏加 `父/母`，例如主角安岁对应 `安父`、`安母`；父母有明确姓名时优先使用姓名。
- 连续多句引号对白逐句拆行。不要把旁白写成对白，不要把反派台词误归给主角。
- `sourceText` 和 `sourceSentences` 必须原样保留输入标点；标点规范化只发生在 `scriptLines` 与 `scriptText`。除说话人标签、场次标题、同一句拆行和上述标点规范化外，不得改变原文任何字词、顺序或事实关系。

随后在当前 Skill Run 工作目录写入相对路径 `adapted_script.json`。必须使用如下结构：

```json
{
  "sourceText":"完整、原样的小说正文。",
  "sourceSentences": [
    {"id":"S001","text":"原文的一个非空正文句子。","scriptLineIds":["L001"]}
  ],
  "scriptLines": [
    {"id":"L001","text":"安岁（旁白）：对应的一句剧本。","sourceSentenceIds":["S001"]}
  ],
  "scriptText":"《标题》一行一句剧本版\\n…"
}
```

- `sourceText` 必须与 `source.txt` 完全一致；不得删段、摘要或改写。必须用脚本把 `source.txt` 的内容原样注入 `sourceText`（例如用 python 读文件后写入 JSON），不得手抄。校验器按 `。！？!?` 与换行切分它，句末标点后的闭引号、闭括号归入当前句，不得拆成孤立句。
- `sourceSentences` 必须与 `sourceText` 切分出的句子按原文顺序逐项完全一致，编号从 `S001` 连续递增；不得先在审计清单中遗漏原文句子。
- `scriptLines` 必须按剧本顺序收录每条旁白或对白，编号从 `L001` 连续递增；每个剧本行**只能**映射一个原文句子，原文长句可拆成多行。所有关联的剧本行都必须是会读出的旁白或对白，不能只用来说明画面。
- `sourceSentences[].scriptLineIds` 与 `scriptLines[].sourceSentenceIds` 必须双向一致；每个 `S` 至少关联一个 `L`。
- `scriptText` 是完整的一行一句纯文本剧本；只有校验通过后，阶段 1–7 才能将它作为单集剧本正文。

写入后必须运行：

```bash
python3 scripts/validate_adapted_script.py adapted_script.json --source source.txt
```

只要出现任何 `ERROR:`，修复剧本或映射并重跑；未输出 `OK: adapted script JSON is valid` 时，**不得进入阶段 1–7**。

### 阶段 1–7：内置分镜流程

将已校验的 `adapted_script.json` 中 `scriptText` 作为本 skill 的单集剧本正文。必须先按该剧本顺序建立内部**语音账本**，再执行资产提取和分镜切分。账本覆盖角色对白、`姓名（旁白）` 或未具名时的 `主角（旁白）`、OS／内心独白、具名与匿名 VO／旁白、画外音、系统／电子语音，以及广播、电话、录音等带明确文本的声音。每个 `S` 关联的剧本行都必须进入账本，并在最终分镜中按顺序读出；`【音效】`、环境声和其他无台词声音不进入语音账本。

总时长由完整语音账本和必要动作镜头自然决定，不设固定上下限；`DURATION_SEC` 只控制单个 storyboard 的主切割时长，不代表整集总时长。正文再长也不得摘要、只抽主线或只生成一个 `DURATION_SEC` 时长的分镜；应按完整内容继续增加 storyboard。

1. 完整读取 [输入归一化](references/01-input-normalization.md)，完成小说到漫解剧本的归一化，并识别场景头、动作、对白、旁白、OS、OV、系统音和快闪。
2. 完整读取 [资产提取](references/02-asset-extraction.md)，建立去重的角色、场景、物品清单及生图提示词。
3. 完整读取 [时长核算与分镜切分](references/03-duration-and-storyboard-splitting.md)，按完整语音账本自然核算总时长，再切功能节拍、分镜和 cNN 子镜头。
4. 完整读取 [镜头编写与导演控制](references/04-shot-writing-and-directing.md)，写空间、姿态、景别、机位、运镜和可见动作。
5. 完整读取 [台词与声音处理](references/05-dialogue-and-audio.md)，逐字保留阶段 0 的旁白和台词，并处理 OS、OV、VO、画外音和系统音。
6. 完整读取 [标签与风格控制](references/06-tags-and-style-control.md)，应用固定风格串、背景虚焦、无文字字幕和配额。
7. 完整读取 [JSON 组装与质量闸门](references/07-json-assembly-and-quality-gates.md)，按精确 schema 组装并完成语义自检和脚本校验。

输出候选 JSON 前，先用语音账本执行**正向对账**与**反向对账**：账本中每项必须按原顺序恰好映射到输出，输出中每段有文本语音也必须能回溯到账本。账本编号仅用于内部推理，不得写入最终 JSON。

仅在输入格式复杂、改编边界不明确或需要比对成品时读取 [输入输出示例](references/08-examples.md)。示例不覆盖阶段 0–7 的规则。

## 校验循环

1. 将候选 JSON 写入当前 Skill Run 工作目录下的相对路径 `candidate.json`。
   - 必须使用相对路径 `candidate.json`；
   - 禁止使用 `/tmp`；
   - 禁止使用任何绝对路径；
   - 禁止使用 `../` 路径。
2. 从本 skill 目录运行：

```bash
python3 scripts/validate_storyboard.py candidate.json --duration-sec <DURATION_SEC> --adapted-script adapted_script.json
```

3. 根据全部 `ERROR:` 修正 JSON，再次运行校验器。
4. 重复直到命令退出码为 0 且输出 `OK: storyboard JSON is valid`。

脚本会验证确定性结构约束，并将最终分镜中的全部有文本语音与 `adapted_script.json` 按说话人、类型、正文和顺序双向对账。动作合理性、1.8x 节奏、导演细节与风格配额仍须人工语义复核；运行脚本前先逐项完成阶段 07 的质量闸门。

## 最终输出

校验通过后，调用 `submit_artifact` 工具提交精确相对路径 `candidate.json`；最终产物只通过该工具交付：

- 不要在回复文本中复制 JSON 本体或其任何片段；
- 不输出中间漫解剧本；
- 不加解释、校验日志或临时文件路径。

不得提交尚未通过校验的候选 JSON。
