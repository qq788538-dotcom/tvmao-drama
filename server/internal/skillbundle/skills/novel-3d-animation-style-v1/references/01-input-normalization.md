# 阶段 01：小说归一化与漫解剧本

先将小说或故事原文归一化为一行一句的漫解剧本，并将逐句覆盖审计写入 `adapted_script.json`；校验通过后，再从其中的 `scriptText` 识别场景头、动作、对白、旁白、OS、OV、系统音与快闪，最后进入资产提取。

> 本 skill 内置 1.8x 加速规则。`__{{DURATION_SEC}}__` 保持为调用时参数。

## 一、小说 → 漫解剧本

输出内部剧本时，先写 `《标题》一行一句剧本版` 和 `人物：`，随后按剧情分场：`【第01场】场景名｜地点｜时间｜内/外`。每个叙述或发声单元单独一行。每条发声行必须构成可直接配音的完整话语，并以 `。`、`！`、`？`、`……` 或表示话语中断的 `——` 结束；原文缺少句末标点时按语气补齐。疑问语气词“吗”后若以空白直接连接下一独立分句，必须用 `？` 替换该空白。

| 小说信号 | 漫解剧本处理 |
|---|---|
| 叙述、动作、心理、背景说明 | 已明确主角姓名时使用 `姓名（旁白）：一句叙述。`；无法确认姓名时使用 `主角（旁白）：一句叙述。` |
| 有引号的内容 | 根据上下文写成角色对白；具名人物动作、神态或说话提示紧邻的引号内容，必须归该具名人物 |
| 无引号但明显人物说话 | 根据上下文写成角色对白 |
| 群体角色 | 只有原文明确是群体发言时才能使用村民、众人等群体角色；不要硬编新名字 |
| 第一人称“我” | 正文中的第一人称必须保持原文，不得把“我”改成主角名；说话人标签可使用已确认的主角姓名 |
| 亲属称谓 | 正文中的亲属称谓必须保持原文；说话人标签中，未具名的主角父母使用主角姓氏加 `父/母`，例如安岁的父母使用 `安父`、`安母` |
| 地点、时间或连续事件明显切换 | 新建一个 `【第NN场】` 场次 |

连续引号内容拆行后仍必须保持同一说话人。不得输出孤立的开引号、闭引号或未配对引号。不能因未立即识别说话人就把具名人物对白改为群体发言。

必须逐句覆盖并逐句读出小说正文：先将完整、原样的输入正文写入 `sourceText`，再按 `。！？!?` 与换行切分为 `sourceSentences`（`S001…`）；句末标点后的连续闭引号、闭括号归入当前句，不得成为独立句。`sourceSentences` 必须与该切分结果按顺序逐项一致；不可先在审计清单中删段、摘要或漏句。再为每条会读出的旁白/对白建立 `scriptLines`（`L001…`）。一个原文句子可因长句拆分对应多个剧本行；一个剧本行只能对应一个原文句子。双方以 `scriptLineIds` / `sourceSentenceIds` 互相引用，任何未映射的 `S` 都是阻断错误。每个已映射的剧本行必须进入语音账本和最终声音，不得仅用画面、资产或镜头描述替代。旁白和对白的字词、顺序与事实必须与小说原文完全一致；只允许为形成可直接配音的完整话语补充、替换或移动标点，并删除被标点替代的空白，不得润色、改写、概括、增删字词或合并原文句子。`sourceText` 与 `sourceSentences` 仍须原样保留输入标点，规范化后的标点只写入 `scriptLines` 与 `scriptText`。校验器会把同一 `S` 关联的全部剧本行正文按声明顺序拼接，并在忽略标点和空白后逐字核对原文，同时确认 `scriptText` 按顺序完整包含全部 `scriptLines`。

小说原文的剧情、叙述、动作、心理、对白、冲突、反转、爽点和结局必须完整保留；不得增加或修改原文内容。除说话人标签、场次标题、同一句拆行和上述标点规范化外，不能改变事实关系，也不能改变原文任何字词或顺序。不要写分镜号、镜头描述或拍摄指导。

写完后从本 skill 根目录执行：

```bash
python3 scripts/validate_adapted_script.py adapted_script.json
```

只有输出 `OK: adapted script JSON is valid`，才能读取 `scriptText` 并继续本文件的第二部分及阶段 02。不得将未经校验的剧本交给资产提取、语音账本或分镜。

## 二、漫解剧本 → 分镜输入

阶段 0 形成的 `姓名（旁白）：`（主角姓名未知时为 `主角（旁白）：`）是带明确文本的声音，和角色对白一样必须原顺序进入语音账本。随后按下表归一化：

| 剧本标记 | 含义 | 处理 |
|---|---|---|
| `姓名（旁白）：…` | 已具名主角叙述 | 写成 `@[角色-姓名](旁白)：“…”`；主角未具名时，`主角（旁白）：…` 写成 `@[角色-主角](旁白)：“…”` |
| `角色（情绪/语气）：台词` | 对白 | 写成 `@[角色-名称]（情绪/语气）：“台词”`，保留括号内原文 |
| `角色OS：…` / `（内心）` | 内心独白 | 写成 `@[角色-名称](内心OS)：“…”` |
| `OV：…` / `▲+OV：…` | 匿名旁白/画外叙述 | 原文保留为 `旁白（画外音）：“…”`；可同步视觉化，但画面不得替代声音 |
| `【叮！系统提示…】` | 系统/电子音 | 写成 `机械的电子音女声：“…”`，数字改中文 |
| `【音效】：…` | 环境声 | 融进画面氛围描写（不单列、不进入语音账本） |
| `【快闪1】…` | 快切蒙太奇 | 拆成 1~2s 的快切子镜头 |

## 语音账本（必须先于资产与分镜）

按漫解剧本顺序提取每个连续发声单元并编号 `A001、A002…`。每项记录类型、说话人、原始情绪括注和原始正文。账本只用于内部推理和最终对账，不写入 JSON。

必须进入语音账本：

- `姓名（旁白）`（或未具名时的 `主角（旁白）`）与其他角色对白；
- OS／内心独白；
- 具名 VO；
- 匿名 OV／旁白；
- 具名或匿名画外音；
- 系统／电子语音；
- 广播、电话、录音等带明确台词文本的声音。

不进入语音账本：`【音效】`、环境声、脚步声、敲门声、风声等无台词声音。它们仍可融入画面氛围，但不参与语音对账。

不得在归一化阶段删除、概括或视觉化替代账本中的任何文本。长语音可在后续拆成连续多个 `cNN`，但必须保留原顺序和完整正文。
