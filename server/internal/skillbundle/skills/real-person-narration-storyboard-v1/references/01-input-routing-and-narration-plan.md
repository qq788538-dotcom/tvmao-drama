# 阶段 01：输入路由与解说计划

先把不同输入归一化为同一种内部 `narration_plan.json`。后续资产、时长、导演和 JSON 阶段只读取这份计划，不再直接自由解释原文。

## 一、输入分类

按以下优先级识别：

1. 出现连续的 `解说：`、`旁白：`、`VO：`、`画外音：`，并已有场景或画面行：`narration_script`。
2. 出现场号、内外景、人物表、动作行和 `角色：台词`：`screenplay`。
3. 以段落叙述、引号对白、第一／第三人称小说语言为主：`short_story`。

不要因为小说含大量引号就误判为剧本，也不要因为剧本含旁白就把所有动作行当成可直接发声的解说。

## 二、三条路由

### A. 已有解说剧本

- 解说、旁白、VO、OS、对白和系统声逐字保留。
- 动作行不进入语音账本，只用于建立视觉证据和场景。
- 长句可按自然意群拆成连续单元；拼回后必须还原原文。

### B. 普通剧本

- 只逐字保留身份揭示、承诺、威胁、质问、反转和结果等决定性短对白；其余对白压缩进解说因果链。
- 把场景变化、动作结果、心理因果和时间跳跃写成高信息密度画外解说。
- 能直接演出的即时动作不必重复口播；但影响理解的因果、身份、时间和结果必须由解说或对白说清。
- 解说不评价原剧本未评价的角色，不新增上帝视角秘密。

### C. 小说／故事原文

- 按非空自然段建立 `sourceUnits`，保留原文顺序和文字。
- 每个源单元至少映射一个 `narrationUnitId`。多个相邻源单元可映射到同一个解说单元，用于合并重复描写和同义信息，但不得跨越时间、场景或因果边界。
- 解说保持原文 POV、人物关系、事实、冲突和语气。第一人称作品默认沿用第一人称，不擅自改成全知第三人称。
- 关键冲突、证据、承诺、威胁和反转中只选择少量一句能落地的原声对白；普通叙述和解释性对白转成快速解说。
- `condensed` 是普通剧本和小说的默认模式：删除不改变因果的修饰，合并重复反应，但保留“谁—为什么—做了什么—证据—结果—反转”。所有源单元仍须映射，防止浓缩变成跳剧情。
- 开头按原文最早可成立的冲突或异常重写为一句钩子；不得为了抓眼把后文真相提前当成既成事实。`N001` 的 `hookRole` 固定为 `primary`。

## 三、计划 schema

字段及顺序固定：

```json
{
  "inputType":"short_story",
  "narrationMode":"fast_recap",
  "fidelityMode":"condensed",
  "baseSpeechCharsPerSec":3,
  "playbackRate":1.6,
  "genreProfile":"comeback",
  "sourceText":"完整原文",
  "sourceUnits":[
    {"id":"S001","text":"原文自然段。","narrationUnitIds":["N001"]}
  ],
  "narrationUnits":[
    {
      "id":"N001",
      "speaker":"解说",
      "mode":"narration",
      "text":"邻居盖房时，一点出路都没留。",
      "sourceUnitIds":["S001"],
      "targetSec":3.0,
      "pauseAfterSec":0,
      "hookRole":"primary",
      "visualMode":"enactment",
      "visualIntent":"先建立道路被新房挤占的核心矛盾",
      "visualEvidence":"新砌墙体贴住地界，狭窄通道只容一人侧身通过",
      "spoilerBoundary":"此时不出现后来挖鱼塘的结果",
      "scene":"两家宅基地通道｜白天｜外"
    }
  ]
}
```

`mode` 只使用：`narration|dialogue|os|vo|system`。

`genreProfile` 只使用：`general_drama|modern_romance|costume_intrigue|suspense|comeback`。它只决定全片色彩和投放视觉基线，不改变剧情事实。

`visualMode` 只使用：

- `enactment`：直接重演正在说的事件；
- `evidence`：道具、环境、伤痕、地界、结果等事实证据；
- `reaction`：用可见行为承载心理或权力变化；
- `establishing`：建立地点、时间、人物与环境关系；
- `transition`：时间／地点变化；
- `flashback`：过去事件，必须有进入和退出边界；
- `dialogue`：人物在场说关键对白。

## 四、语音单元、规划时钟与停顿

- Seedance 2.0 基础口播规划值固定为 3 个语义字符／秒。匿名解说使用 `planningCps = 3 × playbackRate`，`playbackRate` 只使用 1.5／1.6／1.7／1.8、缺省 1.6；角色对白、OS、具名 VO 和系统声使用基础 3 字／秒。这里的倍率只用于时长预算，不是 Seedance 音频控制参数。
- 匿名解说一个单元只说一个意群，常见 8～12 个语义字符，最多 14 个；按缺省规划时钟约占 1.7～3.0 秒。角色直接声音最多 9 个语义字符，保持约 3 秒内的稳定表演和口型。
- `targetSec = ceil((语义字符数 ÷ planningCps) × 10) ÷ 10`，保留一位小数。语义字符只计汉字、字母和数字；由脚本确定性计算，模型不得自行估计。不能把每个单元分别取整到整数秒。
- `pauseAfterSec` 只允许 `0|0.5`。普通连续解说填 0；只有反转揭晓、对白交接、重大结果或时空切换才留 0.5 秒，不给每句机械加停顿。
- `hookRole` 只允许 `primary|support|none`。全篇只有 `N001=primary`；它必须在第一镜与可见证据同时开始。后续可用 `support` 标记承接钩子的第二意群，其余填 `none`。
- 一条长原句拆成多个单元时，来源映射保持相同，顺序拼接不丢事实。
- 解说统一使用 `speaker=解说, mode=narration`；匿名解说不创建角色资产。
- 人物直接对白使用真实角色名和 `mode=dialogue`。

`playbackRate` 不编译进 Seedance prompt。每个 storyboard 的首个匿名解说写成 `解说（画外音，电影解说式快速清晰、连续无拖腔）`；后续连续解说只写 `解说（画外音）`，让第一条简洁声音指令统领本段，不重复堆满提示词。需要精确 1.6 倍速时必须改用统一 TTS 或后期变速。

## 五、视觉证据和剧透边界

每个单元必须回答：

1. 观众在声音开始时具体看见什么事实？
2. 这个画面比“人物走路／转头／皱眉”多提供了什么新信息？
3. 当前最多可以展示到哪一步，哪些后果仍不能提前出现？

心理词必须转换为行为证据。例如“他很得意”应落到“背手踱步、故意停在对方地界中央、看向围观村民”，不能只写“得意地笑”。

完成计划后运行 `scripts/validate_narration_plan.py`；通过后再读取阶段 02。
