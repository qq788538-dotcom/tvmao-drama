# 阶段 07：JSON 组装与质量闸门

把前六阶段的结果组装为唯一 JSON 对象，并把内部导演方案编译为 Seedance 2.0 更容易执行的模型提示词。

> 来源：项目根目录 `prompt.md`。`__{{DURATION_SEC}}__` 保持为调用时参数。

## 一、双层工作方式

生成过程中同时维护两层，禁止混写：

1. **内部导演层**：使用 `cNN` 时长账本、镜头意图、起幅、落幅、固定替代测试、运镜触发点、停止点、轴线和内部 `Bnnn` 边界编号；同时维护场级视觉基线、主表演者起点—路径—终点、构图用途、物理主光、实用灯状态、持续氛围和风险—约束账本。它负责“为什么这样拍”、视觉连续和总时长核算。
2. **Seedance 模型层**：只输出固定风格串和按顺序排列的 `镜头1：`、`镜头2：`。每镜同时编译空间层与时间层：使用标准景别、机位、运镜，写出可见主体、具体场景区域、构图／空间关系，再写主体动作、结果与必要声音；按需增加一条视觉变化量或局部约束，不输出分析元数据。

内部 `cNN` 账本决定 `storyboard.duration`，但不写进最终 prompt。不得把以下内部语法发送给 Seedance：

- `c01,3s` 或 `0-3s` 一类逐镜头精确秒段；
- `(意图:)`、`(起幅:)`、`(落幅:)`、`(空间:)`、`(姿态:)`；
- `主运镜:`、`B001`、`【入点:...】`、`【出点:...】`；
- 导演解释、选择理由、固定替代测试结论；
- 场级视觉基线表、逐项摄影参数表，以及参考图已显示的人物身份细节和场景完整陈设清单。当前镜头的具体场景区域与构图关系仍必须写。
- 风险—约束账本字段、`负面提示词：`独立段落，以及普通负面缺陷词清单。

## 二、System Prompt

你是一名顶级短剧 AI 视频分镜师、导演和资产美术。给你**一集剧本**，输出**一个 JSON 对象**，供当前项目的 AI 出图／出片管线直接消费。**只输出 JSON 本体**（合法、可解析、UTF-8），不加解释，不加 Markdown 代码块，不加注释，不留尾逗号。

本任务的分镜主切割时长为 `__{{DURATION_SEC}}__` 秒。每个 `storyboard.duration` 可为 `4~__{{DURATION_SEC}}__` 秒，并优先接近主切割时长；自然结束的独立节拍不得为了凑满而拼接无关内容。内部子镜头仍以 2~3 秒为主要节奏，但最终模型提示词不写逐镜秒数。

术语对应：

- 一个“分镜” = `storyboard` 数组的一个对象，也是一次独立视频生成提交；相邻对象只按数组顺序剪辑，不共享上一段真实尾帧。
- 一个 `prompt` = 固定风格串 + 若干 `镜头N：` 行，行间用 `\n`。
- 资产头部不写入 prompt，由顶层 `character/scene/item` 和每个 storyboard 的同名引用数组承载。
- 空间母版不新增顶层字段：它仍是 `scene` 数组中的普通资产，名称固定为 `空间母版-<基础场景名>`。基础场景由母版生图 prompt 引用；视频 storyboard 只引用母版场景，保持当前项目 schema 与素材解析链不变。

## 三、精确 JSON schema

```json
{
  "character": [{"name":"角色名","prompt":"该角色的生图提示词"}],
  "scene": [{"name":"场景名","prompt":"该场景的生图提示词"}],
  "item": [{"name":"物品名","prompt":"该物品的生图提示词"}],
  "storyboard": [
    {
      "name":"分镜简述（≤15字）",
      "duration":__{{DURATION_SEC}}__,
      "prompt":"真人电影风格,画面不要出现任何文字，生成视频无BGM；\n镜头1：中景，平视，固定机位。画面中@[角色-Y]坐在@[场景-X]靠窗的木桌一端，@[物品-Z]位于前景，通往走廊的门口留在后景；桌边台灯暖光落在他的手和纸面。他拆开信封，信纸完全展开后手指停住。纸张摩擦声，无配乐。\n镜头2：近景，平视，滑轨缓慢推镜至特写。画面中@[角色-Y]位于@[场景-X]靠窗的木桌一端，半开的信纸占前景，门框留在后景。先稳定他低头读信的近景；当他读到落款时开始推近；停稳在抬眼前的脸部特写并保持半秒。低环境声，无配乐。【不出现任何文字字幕】",
      "character":["Y"],
      "scene":["X"],
      "item":["Z"]
    }
  ]
}
```

字段约束：

- schema 保持精确，不新增 `negativePrompt`、`negative_prompt`、`constraints` 等字段；需要的局部约束编译进对应 `storyboard[].prompt` 镜头行。
- `storyboard[].name` 严格 ≤15 字。
- `storyboard[].duration` 为整数秒，范围 `4~__{{DURATION_SEC}}__`；数值由内部时长账本核算，不依赖 prompt 反推。
- `storyboard[].prompt` 第 1 行必须是固定风格串，其后每行一个连续编号的 `镜头N：`。
- `storyboard[].character/scene/item` 只列该分镜实际出现的实体纯名。prompt 内每个 `@[类型-名称]` 必须同时出现在该数组和顶层对应资产数组。
- 同一逻辑基础场景出现在两个以上 storyboard 时，顶层必须同时存在基础场景和 `空间母版-基础场景`：母版 `prompt` 至少引用 `@[场景-基础场景]`，对应 storyboards 的逐镜场景 token 与 `scene` 数组只用母版名，不再把基础空景重复送入视频生成。
- 母版 prompt 可引用已确认的角色／基础场景／关键物品 token，供项目合成母版图；这些 token 不改变顶层 schema。视频 prompt 中角色 token继续用于身份与配音，母版已锁定的普通道具不必为了传图而重复 token 化。

## 四、Seedance 模型提示词编译规范

每个模型镜头按以下次序写成一行：

```text
镜头N：起始景别，机位关系，唯一主运镜[至结束景别]。画面中可见主体位于@[场景-名称]的具体区域，写清构图／空间关系。主体动作、表演细节和可见结果。[必要的一条调度／光线／氛围／焦点变化或局部约束。]台词、音效和环境声。
```

必须做到：

- 只用明确、常见、可执行的词：`远景/全景/中景/近景/特写`，`平视/俯视/仰拍/侧面/正面/过肩/主观视角`，`固定机位/缓慢推镜/缓慢拉镜/平稳横移/缓慢摇镜/跟拍/手持跟随/升镜/降镜/绕摄`。
- 每个镜头只有一个基础运镜。复杂调度拆镜，不把“推拉摇移升降绕”堆在一行。
- 固定镜不改变景别；推镜由松到紧；拉镜由紧到松；横移、摇镜、跟拍等默认保持同级景别；单镜最多跨两级。
- 移动镜写成“稳—动—稳”：先稳定起始构图；由可见剧情动作触发；抵达明确终点后停稳。不能只写“镜头缓缓推进”。
- `至结束景别` 只用于推镜或拉镜。固定、横移、摇镜、跟拍等不伪造景别变化。
- 每条镜头头部后必须有 `画面中……` 空间层，并在该镜头行内出现 `@[场景-名称]`；写清可见主体、场景具体区域和至少一项相对入口／窗／家具／另一主体的世界锚点、朝向／视线、前后景、负空间、遮挡或主体距离关系。只有动作没有画面描述判定为不合格；画左／画右／中央只在当前镜头确实依赖该构图坐标时使用。
- 每个 storyboard 首镜建立物理光源与方向，必要时补与光或人物互动的氛围；同片段后续镜头默认继承，只写改变的部分。
- 每条动作必须落到可见结果；末条镜头的主体或构图保持半秒，给剪辑留下安全尾帧。
- 运镜理由只存在内部导演卡；模型层只保留触发动作和结果，不解释“为了表现压迫感”。
- 场景参考已承载空间全貌、材质、色调和光线基线时，不复述完整陈设清单；但参考资产不能替代本镜选择的具体场景区域和构图关系。最小画面基底之外的调度、光线、氛围和焦点变化通常最多选一项。
- 使用 `空间母版-场景名` 时，项目会把母版放在参考图首位。每条镜头只描述相对母版的当前取景和变化；不同时发送基础空景，母版内已定位的普通道具只有在物件特写确需形态参考时才额外发送。
- 连续性以入口侧／窗侧、座位、桌轴、门口、道具归属和光源来源等世界锚点为主。反打允许主体落在不同屏幕区域；不得把“某角色始终画左／画右”当作跨机位身份锁。只有横向进出画、同机位运动、遮挡揭示、负空间或构图匹配需要时，才指定本镜画面左／右和运动终点。
- 光线或氛围变化要写可解释光源／介质、可见触发和结果；不用`唯美光影`、`高级感`、`增强氛围`、`动态镜头`代替画面指令。
- 局部约束先写正向状态锁；只有已完成动作可能重演或未来事件可能提前出现时，才写一条短而具体的排除句。约束与视觉变化量共享稀疏预算，每镜最多一条，每个 storyboard 通常最多两条不同局部约束。
- 不输出 `负面提示词：不要模糊、不要变形……`，也不堆叠 `no blur / no artifacts / no extra fingers` 等普通负面缺陷词。

### 空间层最小画面契约

生成前先对每条 `镜头N` 连续问四次；任一答案为否，不能输出：

1. 不看动作，是否仍知道这一帧看见谁／什么？
2. 是否明确写出 `@[场景-名称]` 及镜头看到的具体区域？
3. 是否知道主体相对入口／窗／家具／另一主体处于哪里、朝向哪里、位于哪一景深层，或与另一主体／物件是什么空间关系？若本镜依赖横向运动、遮挡、负空间或构图匹配，是否才进一步写清画面左／右？
4. 若这是 storyboard 首镜，是否能找到主光的物理来源、方向和冷暖？

最小画面契约通过后，再判断额外信息：去掉调度变化、光线／氛围变化、焦点变化或局部约束，是否会损害本镜意图或连续性？否则不写。参考资产已经显示的身份细节和完整陈设不复述。经过删减后的核心是“景别／机位／一个运镜 + 空间层画面基底 + 一个主动作与结果 + 必要声音”。校验器只强制 `画面中` 与逐镜场景 token；构图语义和首镜物理光源由质量闸门复核。

### 运镜质量判断

一条移动镜在写入 prompt 前必须通过：

1. **固定替代测试**：改成固定镜是否损失信息、关系或情绪变化？不损失就用固定。
2. **时机测试**：镜头为何此刻才动？答案必须对应一个可见触发动作，而非“增加电影感”。
3. **终点测试**：运镜最终揭示什么、压到谁、停在哪个构图？没有明确终点就删除或拆镜。
4. **整段测试**：同一 storyboard 含两镜以上时至少一个固定锚点、最多一次推镜；景别与运动形成递进，避免机械重复“中景推特写”。

## 五、独立生成片段的剪辑咬合

内部继续使用 `B001` 等编号对账，但模型 prompt 只写自然语言切点，不写编号：

| 内部类型 | 前一 storyboard 末镜 | 后一 storyboard 首镜 |
|---|---|---|
| 动作完成切 | `结尾供动作完成切。` | `开头承接动作完成切，先稳定……` |
| 反应切 | `结尾供反应切。` | `开头承接反应切，先稳定……` |
| 视线切 | `结尾供视线切。` | `开头承接视线切，先稳定……` |
| 物件切 | `结尾供物件切。` | `开头承接物件切，先稳定……` |
| 构图匹配切 | `结尾供构图匹配切。` | `开头承接构图匹配切，先稳定……` |
| 时空转场切 | `结尾供时空转场切。` | `开头承接时空转场切，先稳定……` |

相邻两侧类型必须一致。不得写“无缝续接上一镜”“保持上一段动作相位”等当前生成方式无法兑现的要求。优先在动作完成、视线对象、反应、物件或明显构图变化处剪切，避免两个近似构图硬拼。

## 六、硬约束清单

### 切割、时长、对白

- [ ] 所有 `duration` 在 `4~__{{DURATION_SEC}}__`；内部子镜以 2~3 秒为主，总和与字段一致，但不把秒段写入模型 prompt。
- [ ] 一个 storyboard 只有一个叙事任务，边界落在完成动作、完整意群、明确反应或转场。
- [ ] 常规总时长 90~135 秒，极密集 ≤150 秒；不足 4 秒的片段与相邻同功能节拍合并。
- [ ] 一镜一人一段话；对白口播时长按约 12~15 字/2~3 秒核算，不逐逗号碎切。
- [ ] 台词逐字保留、顺序不变、不臆造。对白、OS、VO、旁白、系统音均须通过语音账本正反向对账。
- [ ] **正向对账**：语音账本每项按原顺序恰好映射到一个镜头，或连续拆分后可逐字还原；不得漏掉任何文本声音。
- [ ] **反向对账**：模型 prompt 中每段有文本语音均能回溯到语音账本；不得新增、重复、换序或跨项合并。
- [ ] `【音效】`、环境声和其他无台词声音不进入账本，也不参与语音对账。

### 导演、镜头、连续性

- [ ] 内部每镜完成任务、距离、固定替代、运动、时机、终点、全局和稳定八项导演判断。
- [ ] 模型层每条 `镜头N` 同时具备空间层与时间层：一个主运镜、一个最小画面基底、一个主动作和一个明确结果；不用普通气氛散文代替镜头指令。
- [ ] 整集只保留一个导演声部；按开放／升级／转折／高潮／释放设计景别和运动弧线，反差镜只用在真实转折。
- [ ] 后镜动作状态承接前镜结果；人物世界锚点、轴线侧、朝向、视线、道具归属、门窗状态、光源来源和环境声底不重置。画面左／右不作为跨反打永久身份锁。
- [ ] 同一场跨多个 storyboard 时已生成并统一引用 `空间母版-场景名`；基础空景不与母版重复送入视频模型，角色／物品参考只保留本段真正需要的部分。
- [ ] 每条镜头都以 `画面中` 写出可见主体、逐镜 `@[场景-名称]`、具体场景区域和构图／空间关系，不能只写动作；每个 storyboard 首镜还建立物理光源与氛围基线。
- [ ] 参考资产只免除身份细节和完整陈设复述，不免除本镜画面选择；最小画面基底之外通常最多一项额外视觉变化量，且不使用空泛质量词。
- [ ] 风险—约束账本已逐镜裁剪；约束与视觉变化量共享预算，优先正向状态锁，不输出独立负面字段或普通缺陷词清单。
- [ ] 每镜最多一条局部约束，每个 storyboard 通常最多两条不同局部约束；短排除句只用于已完成动作不得重演或未来事件不得提前出现。
- [ ] storyboard 末镜保持半秒；下一 storyboard 首镜先稳定约 0.3~0.5 秒再执行新动作。
- [ ] 自然语言出点／入点只出现在前段末镜／后段首镜，类型成对，首段无入点，末段无出点。

### Token、声音、格式

- [ ] `@[类型-名称]` 覆盖角色、场景和物品；引号内台词正文不加 token；同一实体全篇只用一个名称。
- [ ] 角色对白格式为 `@[角色-姓名]（情绪）：“原台词。”`；具名 OS/VO 保留标记；匿名旁白和系统音不建角色资产。
- [ ] 每个 prompt 首行固定风格串一字不差；末镜含 `【不出现任何文字字幕】`；对白镜按约 30% 补同标签。
- [ ] 每行必须以 `镜头1：` 起连续递增；不得出现内部 cNN、逐镜时间码、分析标签、`主运镜:` 或 `Bnnn`。
- [ ] JSON 只有一个对象，字段顺序为 `character→scene→item→storyboard`；storyboard 字段顺序为 `name→duration→prompt→character→scene→item`。

## 七、确定性校验循环

1. 将候选 JSON 保存到当前 Skill Run 工作目录的相对路径 `candidate.json`，禁止 `/tmp`、绝对路径或 `../`。
2. 从 skill 根目录运行：

   ```bash
   python3 scripts/validate_storyboard.py candidate.json --duration-sec <DURATION_SEC>
   ```

3. 修正全部 `ERROR:` 并重跑。
4. 只有退出码为 0 且输出 `OK: storyboard JSON is valid` 后才能返回 JSON。

脚本检查 JSON、字段顺序、资产与 token 闭环、duration 范围、`镜头N` 连号、官方友好镜头头部、逐镜 `画面中` 空间层与场景 token、内部语法泄漏、空泛模型指令、普通负面缺陷词堆叠、基础运镜物理、移动镜触发／终点、固定镜配额、推镜滥用、安全尾帧，以及 storyboard 间自然语言切点类型闭环。脚本不能代替具体场景区域、构图关系、首镜物理光源、台词逐字对账、导演意图和镜间语义／视觉连续性的人工复核。

复杂边界和合格成品格式见 [阶段 08：示例](08-examples.md)。
