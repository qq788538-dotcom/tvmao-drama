# `miaoju compliance` — Seedance 2.0 合规校验

`doubao-seedance*` 的生成**要求输入素材先通过合规校验**,没过就直接失败。以前提交
校验只能在桌面端画布上手动操作,用 CLI 能把整张画布建好、一跑 seedance 就卡住——素材一多(6 张
人物三视图 + 5 张场景图)等于走不通。现在 CLI 有了这一步。

前置:要校验的节点**已经有内容**了(生成节点得先跑出来,见 [run.md](./run.md))。

## 子命令

| 子命令 | 作用 |
| --- | --- |
| **`miaoju compliance verify <节点ID>...`** | 提交一个或多个节点的素材去校验 |
| **`miaoju compliance status`** | 看全项目每个节点的校验状态 |

```sh
miaoju compliance verify n-abc12345                  # 提交一个
miaoju compliance verify n-a n-b n-c                 # 逐个提交
miaoju compliance status                             # 看全项目状态
```

**典型顺序**:图片节点先生成出内容 → `verify` 提交 → 再跑视频。顺序反了(先跑 seedance 视频)必然失败。

`verify` 是**同步**的:命令返回时已经出结果——通过即为 `active`;不合规或上游出错时命令以非零退出码失败,
错误信息是上游原文,同时该节点状态记为 `failed_permanent`。合规校验走喵剧内置模型 `seedance-asset`,
未启用或上游地址、API Key 未配置时会直接报错,请用户在喵剧 设置 → 模型中心 中配置。

## `status` 取值

| 值 | 含义 |
|---|---|
| `unverified` | 还没提交过校验 |
| `pending` | 正在校验(只在 `verify` 执行期间短暂出现) |
| `active` | 通过,可以用于 seedance 生成 |
| `failed` | 这次失败,可重试 |
| `failed_permanent` | 判定不合规,重试也没用,换素材 |

## 要点

- 入口是**节点 ID**,不是媒体 URL:服务端从画布快照读那个节点的素材,你不用去碰
  对象存储 key,也不用搞一串会过期的签名 URL。
- 校验类型从**节点类型**推断:图片输入/图片生成按图片校验,视频生成按视频,
  音频输入按音频。没有 `--kind` 这种参数,少一处能传错的地方。
- **重复提交是安全的**:已通过且素材没换过的不会再占上游配额。整条命令重跑没有副作用——
  所以脚本里可以无脑先 `verify` 一遍再跑。
- 还没生成出内容的节点会被拒绝——那时候没东西可校验。
- 多节点提交时中途失败会**停在那里**并返回非零退出码,已提交的不受影响。
- `status` 按画布里的节点顺序输出,多次调用行序稳定,可以直接 diff。
- 合规校验只覆盖**画布节点上**的素材;素材库里没挂到节点上的东西还是得回到喵剧桌面端,在画布上手动提交。

完整选项以 `miaoju compliance <子命令> --help` 为准。
